# Spec F08-E01-T01 — Factory mode works with one agent, two stay accepted

## Summary

- Goal: A Factory project runs from claim to done with one agent in the Agent identity table; two or more agents are accepted and nothing requires them
- Rules: BR-007, BR-008, BR-009, BR-015, BR-016
- Tags: single agent solo roster role QA review Agent identity scripts/project_docs.sh scripts/project_docs.ps1 scripts/smoke_test.sh SKILL.md references/factory.md templates/AGENTS.factory.md AGENTS.md
<!-- context:end -->

User request (2026-11-16): if the work is done with a single agent that must be valid. The process cannot
stop on the requirement of two agents. It may ask the agent to act in a different role, but not to find
a second agent. Two agents are accepted, they are not required.

## Decisions (ADR-098)

What stopped a lone agent today

- `check` failed with fewer than two rows in the table and with no QA or BOTH role.
- `claim`, `next` and `advance` refused an agent whose role was not the one of the phase, so a lone DEV
  agent could never take the SPEC phase.
- `review` and the SPEC to RED gate refused a review by the agent that holds the task.

The rule

- The table is solo when it has exactly one row, of any Kind (an em dash row is not a row): an AI agent
  next to a HUMAN row is not solo, and that table needs a QA or BOTH role. Only Factory mode reads
  it that way; classic mode and every command outside the Factory paths below read the table as before
  (BR-007, BR-008).
- `check` (Factory only): a table with no row fails with `ERROR: Agent identity needs at least 1 agent
  in Factory mode (found 0)` and no message about the QA role. One row of any valid role passes. Two
  rows or more still need one with role QA or BOTH (`ERROR: Agent identity needs an agent with role QA
  (or BOTH) in Factory mode`). An invalid role fails as before. The old `at least 2 agents` text is gone.
- In a solo table the only agent covers every role. `claim` (phase role), `advance` (the role of the
  agent that takes the next phase, and the default assignee, which is that agent), `next` (what the
  agent can work on and review) and `review` (the role of the reviewer) read its role as BOTH.
  `handoff`, `done`, `retro`, `status`, `digest` and `rotate` never read the role and do not change. An agent
  that is not the one in the table is refused as before ("is not in the Agent identity table").
- In a solo table `review` accepts a review by the agent that holds the task, with or without the
  setting `Independent review`, and does not print the self-review warning nor the DEVELOPER warning
  (they describe a mistake that is not one here). It writes `- Cross-model: NO`, as for any review by
  the same model, so the digest and the audit queue still tell it apart from an independent review.
  `PROJECT_DOCS_REQUIRE_INDEPENDENT_REVIEW=1` still refuses it (an explicit request for strictness).
- In a solo table the SPEC to RED gate accepts a `Review: PASS` left by the same agent. With
  `Independent review` YES (the default) the review must exist and the spec hash must still match
  (`handoff` records it): the review stays a separate step, done in the QA role. With NO the gate asks
  for neither, as in any table (ADR-051). `next` reads the role of the lone agent as BOTH in all its
  branches: its task, a task assigned to it, a TODO row of the Roadmap and the review of its own handoff.
- Everything else stands: `exit=` markers, RED evidence, tests unchanged since RED, `done` only after
  a `Review: PASS`, WIP and fix limits.
- Two agents or more: no change at all. A self-review is refused, a reviewer needs the role QA or BOTH
  (SPEC for a spec), the spec review comes from another agent (BR-009).

Instructions

- SKILL.md and references/factory.md say that Factory mode needs one id, that a lone agent covers every
  role and reviews its own work in a separate step in the QA role, and what to do: replace the rows of
  the table by one row for the agent (`BOTH` is the clearest role); `check` then warns, at most ten
  lines, about ledger entries by the ids that were removed. templates/AGENTS.factory.md and this
  repository's AGENTS.md carry a short sentence (one id works alone, two or more need a QA role) and
  keep both size limits: the fresh Factory project context stays at or below 6912 bytes and `context`
  of this repository at or below 8192. README.md (the sentence about a second agent, the `advance` row
  and the gates paragraph) and docs/features/ia-factory.md (the two-ids row, BR-009 and the `advance`
  case) are reworded to say another agent reviews when there is one. The classic template stays as it
  is (BR-008).
- evals/evals.json gets one case for the lone agent.

## Out of scope

- A command that rewrites the table for the user (`init` keeps the default table; the agent edits one row)
- Requiring that the review comes from a fresh context or another model: the skill only asks for a separate step in the QA role
- Changing the dispatcher, which hands turns between several CLIs and is not used by one agent
- Any change when the table has two rows or more
