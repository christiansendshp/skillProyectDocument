# Spec F07-E01-T01 — HTML summary page with kanban and PO questions

## Summary

- Goal: The agent produces docs/summary.html, a one-file page with what was done, a kanban of every task and the questions the PO must answer on the page
- Rules: BR-004, BR-007, BR-008, BR-014
- Tags: summary ask answer html kanban questions PO ProductDescription scripts/project_docs.sh scripts/project_docs.ps1 scripts/smoke_test.sh SKILL.md references/workflow.md templates/AGENTS.factory.md AGENTS.md
<!-- context:end -->

User request (2026-11-07): the page has at least three sections. 1) What was done so far: clear, at
most 30 words, one idea per paragraph, naming the task. 2) A kanban of the tasks and the state of each.
3) The open questions of the PO: a clear question, an example, answerable right there.

## Decisions (ADR-095 to ADR-097)

Page and command

- `summary [en|es]` writes `docs/summary.html` (default `en`; `es` changes only the labels) and prints
  exactly `project_docs summary: docs/summary.html written` on stdout, warnings on stderr, exit 0. Any
  other language is refused.
- The page is one self-contained file: inline CSS and JS, no network. No text from the docs goes inside
  `<script>` (the JS reads the page), attributes use double quotes only, and every text from the docs is
  escaped for `&`, `<`, `>` and `"`. It is a generated file the agent commits; it is not a contract file
  (BR-004 does not apply to it).
- Same bytes from sh and ps1: UTF-8 without BOM, LF line ends, labels written with HTML entities so the
  PowerShell source stays ASCII, every doc read with its BOM and CR removed, words split on spaces and
  tabs only (a non-breaking space is part of a word), timestamps compared as plain strings, no clock.
- The ledger means the archives `docs/history/*.md` in name order (byte order) and then
  `docs/Agentslog.md`, read in that order. An AUDIT entry never counts as a task's last entry (a
  reviewer audits a task after its DONE). A DONE entry with the same task and timestamp as a DONE entry
  already read is a copy left by `rotate`: it is skipped, so the first one keeps its Name and Summary.
  "Updated" is the largest entry timestamp of the ledger (`-` when there is none). The page carries
  `<!-- project-docs-source: <T> q=<R>/<C> -->` where T is the largest timestamp of a DONE entry of the
  ledger (or `none`), R the number of rows of `## Open questions` and C how many are CONFIRMED.
- A tab in a doc read for the page, the marker or `answer` is read as a space, so a field never splits
  in two. T keeps only digits, `T`, `Z`, `:`, `.`, `+` and `-` (`none` when nothing is left), so text
  from the ledger can never close the comment.

Section 1, `<section id="done">`

- The done list: every task whose last entry in the ledger is DONE, ordered by the timestamp of that
  entry, newest first, a tie going to the entry read later.
- One `<p class="done">` per task, at most 30: `<span class="ref">ID</span> <strong>Name</strong>:
  Summary`, Name and Summary from that DONE entry; an entry with no Name takes the Roadmap Name, and
  with neither the `<strong>` part and its colon are left out (`<span class="ref">ID</span> Summary`).
  Name and Summary together are at most 30 words: the Name keeps its first 30 words and the Summary its
  first 30 minus the words the Name kept (never below 0); the kept words of each are joined by one space
  and, when words were dropped, the paragraph ends with ` ...`. A cut prints
  `WARN: <ID> paragraph is <N> words; the page shows 30` (N counts Name and Summary).
- More than 30 tasks: one `<p class="more">` that counts the rest. No task: one `<p class="empty">`.

Section 2, `<section id="kanban">`

- Five columns in this order, each a `<div class="column" id="col-...">` with one card per line:
  `todo` To do, `doing` In progress, `review` In review, `paused` Paused, `done` Done. A card is
  `<div class="card" data-id="ID"><span class="ref">ID</span> <span class="name">Name</span>` and an
  optional `<span class="meta">...</span>`.
- Cards come from the Roadmap rows that have an ID, a Name and a Status (any section, placeholders
  skipped, an ID seen twice counted once at its first row), the tasks of the live ledger, and the done
  list. The column of a task: its live ledger state when it has one (ADR-021): IN_PROGRESS and a REVIEW
  whose Review is FAIL to In progress with the holder as meta; REVIEW to In review with the holder;
  PAUSE to Paused with the pause category; ASSIGNED to To do with `assigned to <agent>`; DONE to Done.
  A card shows the Roadmap Name, else the last Name of the task in the ledger, else the ID.
  A ledger word with no column (AUDIT included), or no live state, falls back to the done list (Done), then to the
  Roadmap Status (TODO, IN_PROGRESS, PAUSE, DONE); a task with none of them has no card.
- The Done column lists the done list in its order, then DONE Roadmap rows missing from it in file
  order; 15 cards at most, then `<div class="more">+N</div>`.

Section 3, `<section id="questions">`

- Questions live in an optional `## Open questions` table of docs/ProductDescription.md with the header
  `| ID | Question | Example | Blocks | Status | Answer |`, IDs `Q-` and three digits at least, and the
  epistemic Status: unresolved while open, CONFIRMED once answered.
- Every row not CONFIRMED is an `<article class="question" data-id="Q-NNN">` with the question, the
  example, what it blocks (left out when `—`) and `<textarea data-id="Q-NNN">`. CONFIRMED rows are
  listed apart, each with its answer and no textarea. No open row: one `<p class="empty">`.
- Buttons `id="copy-answers"` and `id="download-answers"` build the same text: one `Q-NNN: answer` line
  per textarea that holds more than spaces, line breaks of the answer turned into spaces. The PO hands that text to the
  agent, who applies each line with `answer`. Drafts are kept in localStorage under
  `project-docs:<page path>:<Q-ID>`, guarded, as a convenience only.

Commands for questions (any agent, no claim needed, under the docs lock)

- `ask <question> <example> [blocks]`: adds `## Open questions` before `## Out of scope` (at the end
  of the file when that heading is missing) with a one-line intro and the header, and appends a row with
  the next free number (three digits at least), the question, the example, the blocks or `—`, the
  unresolved Status and Answer `—`. Prints `project_docs ask: Q-NNN recorded`. Text is cleaned like
  every other field (line breaks to spaces, `|` to `/`, trimmed). An empty question or example is
  refused.
- `answer <Q-ID> <text>`: cleans the text the same way, writes it as the Answer and sets CONFIRMED.
  Prints `project_docs answer: Q-NNN answered`. Refuses an empty text, an unknown ID and a question
  already CONFIRMED.

Check

- Only when `## Open questions` exists: the header above, the ID format, a Question and an Example that
  are not empty or `—`, and an Answer that is not empty or `—` on a CONFIRMED row. Errors:
  `ERROR: docs/ProductDescription.md Open questions has invalid ID format: <ID>`,
  `ERROR: docs/ProductDescription.md question '<ID>' has an empty Question` (or `Example`),
  `ERROR: docs/ProductDescription.md question '<ID>' is CONFIRMED without an Answer`,
  `ERROR: docs/ProductDescription.md ## Open questions needs the header | ID | Question | Example | Blocks | Status | Answer |`.
- In Factory mode only: `WARN: docs/summary.html is missing; run summary` when there is no page, and
  `WARN: docs/summary.html is older than the ledger; run summary` when its source marker differs from
  the one the docs give now: a new DONE, an `ask` or an `answer` makes it stale; a rotation keeps it the
  same, so it draws no warning. A task reopened after DONE leaves section 1 without a warning (known
  limit). Older Factory fixtures of the smoke test and dogfood.sh that run `check` may need `summary`
  first or accept the warning; they are adjusted in RED, not in GREEN. A
  classic project sees no new output (BR-007, BR-008).

Instructions

- SKILL.md, references/workflow.md, templates/AGENTS.factory.md and this repository's AGENTS.md: at
  Close, run `summary` after `rotate` and before `check` (the Close step is reworded in place, so
  `context` stays at or below 8192 bytes here and in a new Factory project); write each `done` summary as one plain idea
  that fits 30 words with the task Name; record a question for the PO with `ask` and apply the PO's
  answers with `answer`. The classic template stays as it is (BR-008).

## Out of scope

- A server or any write from the browser to the repository: the page hands answers back as text
- Running summary automatically from done, rotate or check (it would change their output, BR-007)
- Adding the Open questions section to the templates or to existing projects by migrate
- Turning HYPOTHESIS BR rows into questions; the agent asks with ask when it needs the PO
